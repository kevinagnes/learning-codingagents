## The artifact: the image-removed marker

This is the whole string, verbatim. It replaces inline image bytes when a request crosses the
image size trigger, so the model does not describe a picture it can no longer see.

```
// packages/core/src/session/model-request.ts:45
const IMAGE_REMOVED =
  "[This image was removed to reduce the request size and is no longer visible. Do not make claims about its contents from memory. If needed, retrieve it again with an available tool or ask the user to attach it again.]"
```

The episode reads it without the brackets and without the constant's name. The three
sentences do three jobs: state the loss, forbid reconstruction from memory, and give a route
back.

## The output limit

Four constants and one function carry the policy: a fallback when the catalog has no output
limit, a hard ceiling, a separate ceiling for summaries, the estimation margin, and a floor.

```
// packages/core/src/session/model-request.ts:47
const GENERATION_KEYS = new Set(Object.keys(GenerationOptions.fields))
// Used when the catalog has no output limit for the model.
const OUTPUT_TOKEN_FALLBACK = 32_000
// No reply needs more, however much the model allows.
const OUTPUT_TOKEN_MAX = 256_000
// A summary never needs more, and a request asking for more cannot be shrunk to fit a window the catalog overstates.
const SUMMARY_OUTPUT_MAX = 32_000
// Prompt text is estimated at about 4 characters per token, which can run low on dense text such as code.
const ESTIMATE_ERROR = 0.15
// Never ask for less; only reachable with automatic compaction off, since it keeps the window from filling this far.
const OUTPUT_TOKEN_MIN = 1_024
```

The budget itself. The requested cap is the catalog limit, clamped by the hard maximum and,
for compaction, by the summary maximum. The room is the window minus what the provider
measured and minus the padded estimate. The limit is the smaller of the two, never below the
floor.

```
// packages/core/src/session/model-request.ts:87
/** The default output limit: the catalog limit, fitted to the room the prompt leaves in the context window. */
export const outputLimit = (
  limit: Model.Info["limit"],
  kind: "primary" | "compaction",
  inputTokens?: Input["inputTokens"],
) => {
  const model = Math.min(limit.output > 0 ? limit.output : OUTPUT_TOKEN_FALLBACK, OUTPUT_TOKEN_MAX)
  const requested = kind === "compaction" ? Math.min(model, SUMMARY_OUTPUT_MAX) : model
  if (inputTokens === undefined || limit.context <= 0) return requested
  const room = limit.context - inputTokens.measured - Math.ceil(inputTokens.estimated * (1 + ESTIMATE_ERROR))
  return Math.min(requested, Math.max(OUTPUT_TOKEN_MIN, room))
}
```

When the reply does hit the limit, the next step is told why, and told what not to do.

```
// packages/core/src/session/runner/llm.ts:38
const CONTINUE_AFTER_OUTPUT_LIMIT =
  "Your last response hit the output token limit (stop reason: length). Do not apologize, recap, or repeat yourself. Break the remaining work into smaller pieces."
```

The three sentences map to three failure modes: thinking the user interrupted, restating what
was already written, and repeating the same oversize attempt.

## Normalizing and bounding a result

Every result shape folds into content, and image parts are decoded, resized, or replaced by a
counted note with a reason.

            mime: result.mime,
          })),
          Effect.catchTag("Image.ResizerUnavailableError", () => Effect.succeed(item)),
          Effect.catchTag("Image.DecodeError", () => Effect.succeed("decode" as const)),
          Effect.catchTag("Image.SizeError", () => Effect.succeed("size" as const)),
        )

      const note = (reason: "decode" | "size", text: string) => {
        const count = normalized.filter((item) => item === reason).length
        if (count === 0) return []
        return [{ type: "text" as const, text: `[${count} image${count === 1 ? "" : "s"} omitted: ${text}]` }]
      }
      return [
        ...normalized.filter((item) => typeof item !== "string"),
        ...note("decode", "could not be decoded."),
        ...note("size", "could not be resized below the image size limit."),
      ]
    })

## Fitting the reply, and the cache

`prepare` sizes the output limit for a request of `budget` tokens. `deliver` can send a
larger request when it cannot shrink the conversation further, so `fitOutput` lowers the
limit again to the room the request being sent actually leaves. The two numbers must be
computed from the same request, or input plus requested output can exceed the window.

For compaction, the budget counts as measured, deliberately without the primary-request
margin — otherwise the conservative margin would clamp every summary to the floor. The
summary cap is a safety valve: a request that asks for more cannot be shrunk to fit a window
the catalog overstates.

Compaction is the most cache-destructive event in a session because it rewrites the early
context. Three choices bound the damage:

- The checkpoint is rendered as a single user message at the front, so everything after the
  newest exchange is unchanged and stays cached.
- The system prompt is assembled in a cache-stable order, and compaction does not reorder it.
- A prompt cache key travels with every request, derived from the session affinity, so cached
  prefixes are looked up per session.

The result is one miss, not zero, and then caching resumes until the next threshold.

## Vocabulary from this episode

Full definitions in [`../appendices/D-glossary.md`](../appendices/D-glossary.md).

- **Measured** — the provider's own usage at the most recent response: input, cache reads,
  cache writes, output, and reasoning.
- **Estimated** — the text since that response, at about four characters per token, with a
  margin.
- **Room** — the window minus measured minus the padded estimate; the space left for a reply.
- **Output limit** — the smaller of the model's cap and the room, with a floor and a ceiling.
- **Truncation marker** — the line that states which lines were kept, how many existed, and
  where the full output is saved.
- **Omission note** — the counted, reasoned replacement for an image that could not be
  decoded or resized.
- **Settlement** — the uninterruptible point at which a tool result is recorded and published.
- **Cache read** — provider-side reuse of an unchanged request prefix, charged below fresh
  input.
