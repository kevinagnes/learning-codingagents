## The artifact, and the description it comes from

The episode reads the load-bearing part of the read tool description. Here is the whole
description, with its anchor.

```ts
// packages/core/src/tool/plugin/read.ts:43
          description:
            "Read the contents of a file or directory. Supports text files, images, and PDFs. Images and PDFs are presented directly to the model. Each text line is prefixed by its 1-based line number as <line>: <content>. The prefix is for reference and is not part of the file content. Directory entries are returned one per line. Use offset and limit to read large files or directories in sections. Prefer one larger read over many small slices, and use grep to find specific content in large files.",
```

The spoken read starts at "The prefix is for reference" and drops the first sentence, because
the line-prefix format it names contains a digit. Nothing inside the quote is reworded.

## The longest description in the toolkit

Every sentence here answers a failure the model would otherwise hit: the copied line prefix,
line-ending preservation, the unique-match default, and the disambiguating remedies.

```ts
// packages/core/src/tool/plugin/edit.ts:222
          description:
            "Edit the contents of a file by finding and replacing exact text. When editing text from Read output, preserve the exact indentation (tabs or spaces) and omit the line-number prefix, such as `1: `. Never include the prefix in oldString or newString. Write line breaks as \\n; the file's existing CRLF or LF line endings are matched and preserved. To change line endings themselves, make oldString and newString differ only in \\r; that edit applies to the exact bytes. If there is no exact match, the edit retries while ignoring typographic quote, dash, and space variants, then trailing whitespace on each line. The edit fails if oldString is not found. By default, oldString must identify a UNIQUE location. Multiple matches FAIL unless replaceAll is true. Add more surrounding context to disambiguate, or set replaceAll to true to replace every occurrence. Use replaceAll when the change should apply to every occurrence, such as renaming a variable.",
```

## The background contract, and the bound that backs it

The timeout default lives beside the instruction the model is given about waiting.

```ts
// packages/core/src/tool/plugin/shell.ts:23
export const name = "shell"
export const DEFAULT_TIMEOUT_MS = 2 * 60 * 1_000

const BACKGROUND_INSTRUCTION =
  "You will be notified automatically when the command finishes. The notification will include the command's output. Unless the user explicitly asks otherwise, DO NOT poll for completion, even if you need the final result to continue. Repeatedly sleeping and reading or searching the output file is polling, not useful work. You may read the current output if it lets you do useful work now, but do not repeatedly check it while waiting for the command to finish. Keep working on anything that does not depend on the result. If you have nothing else to do, end your response; you will be resumed automatically when the command finishes."
```

The timeout message names the value and the remedy, so the model retries with a larger number
rather than giving up.

## The code mode split

Tools are partitioned once per snapshot. The share that stays native is sorted by name; the
rest become the code mode inventory, and the rendered catalog is cached per registry revision.

```ts
// packages/core/src/tool.ts:234
          const direct = new Map(Array.from(active).filter(([, tool]) => tool.options?.codemode === false))
          const codeModeTools = new Map(Array.from(active).filter(([, tool]) => tool.options?.codemode !== false))
          const namespaces = data.namespaces
          const codeModeInventory = { tools: codeModeTools, namespaces }
          const codeModeEnabled = !whollyDisabled("execute", rules)
          const codeModeTool = codeModeEnabled
            ? CodeModeTool.create(codeModeInventory, (name, tool, input, context) =>
                beforeExecute(name, input, context).pipe(
                  Effect.flatMap((event) => executeTool(tool, name, event.input, context)),
                ),
              )
            : undefined
          const names = Array.from(codeModeTools.keys()).join("\0")
          // Discovery is immutable for a registry revision and visible tool set. Keep request
          // definitions/executors fresh, but share the much larger rendered catalog across steps.
          const codeModeCatalog = !codeModeEnabled
            ? undefined
            : catalog?.data === data && catalog.names === names
              ? catalog.value
              : CodeModeTool.catalog(codeModeInventory)
```

## Why only the first hook may fail

The asymmetry is in the types. The before hook can reject the call with a tool error; the
after hook cannot fail at all, because the tool has already run.

```ts
// packages/plugin/src/effect/tool.ts:20
export interface ToolHooks {
  readonly "execute.before": {
    tool: string
    readonly sessionID: Session.ID
    readonly agent: Agent.ID
    readonly messageID: SessionMessage.ID
    readonly id: Tool.CallID
    input: unknown
  }
  …
}

// Only execute.before may fail: a Tool.Error rejects the call before the tool runs.
export interface ToolFailures extends Record<keyof ToolHooks, unknown> {
  readonly "execute.before": Tool.Error
  readonly "execute.after": never
}
```

## Vocabulary from this episode

Full definitions in [`../appendices/D-glossary.md`](../appendices/D-glossary.md).

- **Tool description** — the paragraph that travels with a tool definition on every request.
- **Editing family** — patch, or edit plus write. A model sees one family at a time.
- **Background command** — a job that returns immediately and settles into a synthetic message.
- **Code mode** — one execute tool plus a rendered catalog of the other tools.
- **Catalog** — the budgeted, delta-updated tool listing delivered as instructions.
- **Tool hook** — the before and after callbacks around a tool call; only the first may fail.

Never call a step a turn.
