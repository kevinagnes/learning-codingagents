## The ladder, in full

The episode reads the names and the invariant column. The topic also carries, for each
milestone, what breaks without it and the smallest test that proves it. The goals and the
invariants are reproduced here.

| # | Goal | Introduces |
|---|---|---|
| M0 | One streamed model call behind a REPL | A mandatory terminal event; a canonical event union |
| M1 | Tools plus filesystem read and write | A registry snapshot and a single call seam |
| M2 | Durable session history | An append-only log ordered by `seq` |
| M3 | Event sourcing and projections | Event to projector to read model in one transaction |
| M4 | The inbox with steering and interrupt | Admission is not delivery; `steer` versus `queue` |
| M5 | Permissions and questions | `ask`/`allow`/`deny` and the defect tunnel |
| M6 | Token budgeting and compaction | Measured plus estimated budget; summary plus verbatim recent window |
| M7 | Retries, overflow recovery, crash resume | `outputStarted`; the write-ahead claim; stale settlement |
| M8 | Subagents and jobs | A child session, a depth limit, a durable completion notice |
| M9 | Snapshots, diffs, revert | Content-addressed per-step captures; stage, clear, commit |
| M10 | The server and live event stream | Durable facts versus ephemeral hints |
| M11 | CodeMode, MCP, skills (optional) | Replayable dynamic tool and instruction sources |

The build invariant: each milestone's test passes on its own, and still passes unmodified after
the next milestone lands. The one deliberate exception is M1's in-memory loop, whose observable
behaviour survives even as its implementation is replaced.

## The loop and the settlement

The outer loop is four lines. There is no inner loop over tool results, and the exit type names
the only ways out.

```
// packages/core/src/session/runner/llm.ts:191
      while (true) {
        const next = yield* advanceToStep()
        if (next._tag !== "Ready") return next
        continuing = yield* runStep(next.context, step)
        step++
        force = false
        entering = false
      }
```

One attempt makes one model stream call. The comment is the roadmap's thesis in one line: read
to the end so the next request can reuse the response.

```
// packages/core/src/session/runner/step.ts:106
    // Read to the end, not just the finish event, so the next request can reuse this response.
    const providerStream = llm.stream(input.prepared.request, input.prepared.options).pipe(
```

The record is an immutable snapshot of what has been settled so far. `needsContinuation` is
derived from the tool states, not stored as an intention. That expression is the difference
between a resumable step and a crash-prone loop.

```
// packages/core/src/session/runner/publish-llm-event.ts:652
    /** Immutable snapshot of everything recorded for this step so far. */
    record: (): StepRecord => ({
      outputStarted,
      providerFailed,
      failure: stepFailure,
      finish: stepSettlement,
      needsContinuation: Iterable.some(
        tools.values(),
        (tool) => !tool.providerExecuted && (tool.called || tool.settled),
      ),
    }),
```

The doorbell is the whole fix for "two executions for one session." Work recorded during an
execution rings it; it does not start a second fiber.

```
// packages/core/src/session/run-coordinator.ts:32
/**
 * One execution is a busy period for one key: one fiber that drains from the first wake
 * until the key would stay idle. `pendingWake` is the doorbell: work recorded during the
 * execution rings it with the scope that work needs, and the execution loop drains again
 * instead of ending. The doorbell closes the gap between a drain's last eligibility check
 * and the idle transition, since those cannot be one atomic step. `done` resolves joiners
 * with this execution's exit.
 */
```

## Vocabulary from this episode

Full definitions in [`../appendices/D-glossary.md`](../appendices/D-glossary.md).

- **Milestone** — one rung of the build ladder, with one goal and one invariant.
- **Gate** — a milestone whose test must pass before the next begins and must still pass at the
  end. Not a phase.
- **Invariant** — the one rule a milestone introduces and later milestones only read.
- **Settlement** — writing the terminal durable facts for a span of work.
- **Terminal event** — the event that ends a model stream. A stream without one is a failure.
- **Write-ahead claim** — a durable marker written before work runs and released at a terminal.
- **Defect tunnel** — carrying a decline past fault-tolerant boundaries so it can never become
  model-visible output.
- **Doorbell** — the pending wake that makes a running execution drain again instead of starting
  a second fiber.
- **Content-addressed capture** — a snapshot named by the hash of its contents.
