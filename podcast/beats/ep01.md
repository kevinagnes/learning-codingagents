# Beat sheet — Episode 1 — The loop is the product

Topics 0.1 and 0.2. Runtime target 25 minutes. Cast: HOST, CO-HOST, EXPERT (once). Artifact:
the repository's rule against an in-memory tool loop.

## Beat 1 — An agent is five things

- **Claim.** An agent is five wired ingredients, not a prompt.
- **Source.** Part 0, § 0.1.
- **Co-host question.** Why is permission grouped with the engine parts, and what makes this an
  agent rather than a script that calls an interface?
- **Mechanism.**
  - The five: a loop, tools, a filesystem, persistence, permission.
  - Four of the five exist because things go wrong; only the loop is about the task.
  - The model chooses the tool and its arguments at runtime, so the control flow is generated.
  - A tool is part of the model's interface and travels with the request.
- **Takeaway (spoken).** One loop, four things that keep it survivable, and a control flow
  nobody wrote.
- **Words.** 584.

## Beat 2 — Why the obvious loop fails

- **Claim.** The naive in-memory loop fails in five structural ways, and they have one cause.
- **Source.** Part 0, § 0.1.
- **Co-host question.** Defends the naive loop, then names the single cause: the state is in
  the wrong place.
- **Mechanism.**
  - Loop has no memory of itself; tools run ungated; the transcript grows; nothing is
    observable; nothing can be steered.
  - Each maps to one of the five ingredients.
  - Four properties, one cause: where the state lives.
  - The fifth cost is a retry that cannot tell done from not done.
- **Takeaway (spoken).** The state is in the wrong place.
- **Words.** 555.

## Beat 3 — One call per step, and the part that looks wrong

- **Claim.** A step is one model call and one durable record, and there is no loop over tool
  results in memory.
- **Source.** Part 0, § 0.1.
- **Co-host question.** "That sounds slower. You are paying for a round trip where a local
  loop would keep going."
- **Mechanism.**
  - What the record holds: the request, every streamed event, and how it finished.
  - The finish is the input to the next decision.
  - The seam between asking and acting is what permission, persistence, and steering need.
  - Alternatives rejected: a library's built-in tool loop, and a caller-owned continuation.
  - EXPERT appears here, once.
- **Takeaway (spoken).** The call is stateless, and the decision to continue is durable.
- **Words.** 612.

## Beat 4 — The map, and the scope question

- **Claim.** Contracts point inward, and every service declares whether it belongs to the
  process or to a working directory.
- **Source.** Part 0, § 0.2.
- **Co-host question.** "Why not make everything process wide? It would be simpler."
- **Mechanism.**
  - The dependency direction: contracts at the bottom, then the model boundary beside the
    runtime, then the runtime, then the surface and the server.
  - The contracts are the shared identity, so there is one session shape, not one per layer.
  - Global services and Location-scoped services, declared by construction.
  - The single seam where a process-wide coordinator routes a session to its directory.
  - The vocabulary: step, execution, drain, turn.
- **Takeaway (spoken).** Scope is declared, not implied.
- **Words.** 623.

## Artifact

The repository's rule: one explicit model stream call per step, continuing from reloaded
history, with no in-memory tool loop. Read aloud, then interpreted: "one explicit call" is the
step, "reloaded history" is the resumability, and the prohibition is a rule for the future.
A production note records the one substitution (a code identifier cannot be spoken).
Words: 285.
