## Beat 1 — Selecting once, loading every step (649 words)

**Claim.** Building a request happens in two phases, and only one of them may run again on
every step.

**Source.** 4.1, selection versus loading.

**The question the co-host raises.** One function that resolves everything is easier to write
and easier to read, so what breaks if the two phases are folded together? And if the split is
about cost, is there anything one function could not do at all?

**Mechanism.**

- Selection fixes identity: the session, the agent, the instruction sources, and a frozen tool
  snapshot. It resolves them in parallel and then fixes the order of the result.
- Loading adds the two things that move: the resolved model and the active history, plus the
  frozen instruction baseline text.
- Selection carries no model and no messages; both phases return the same tool snapshot, so the
  advertised tools cannot shift mid-execution.
- The split also buys reuse: an auxiliary flow such as naming a session resolves only the
  capabilities it needs, and one selection can be loaded against another model.
- Guards: selection refuses to assemble for a session in another directory, and loading passes a
  provenance boundary into history so only replayable windows are included.

**Takeaway.** Resolve identity once, and reload the state as often as it moves.

**Hand-off.** The co-host asks where the second part of the prompt comes from.

## Beat 2 — The prompt is parts (646 words)

**Claim.** The system prompt is not one string; it is a list of parts, and an ordinary request
has exactly two.

**Source.** 4.2, system-prompt assembly.

**The question the co-host raises.** The file on disk looks like one block of prose, so where
does a second part come from? And what happens when an agent brings its own system prompt?

**Mechanism.**

- Part one is the base prompt with the tool guidance spliced in at a placeholder, so it is
  generated per request rather than stored.
- Part two is the frozen instruction baseline, always appended, and the part that can later be
  replaced by a delta without touching the first.
- An agent's own system prompt replaces the first part outright; the baseline still follows, so
  the override is honoured rather than silently prefixed.
- Empty parts are filtered out, so a zero-length part never occupies a slot.
- The load-bearing line is the system reminder sentence: the harness injects policy notes inside
  the user turn, and that line is what stops the model treating them as user text.

**Takeaway.** The prompt is parts in a fixed order: the harness voice, then the frozen project
baseline.

**Hand-off.** The co-host asks about the placeholder in the middle.

## Beat 3 — Guidance depends on the tools (628 words)

**Claim.** The middle of the base prompt is a placeholder that becomes a different list of
lines depending on which tools are in this request.

**Source.** 4.2, conditional tool guidance.

**The question the co-host raises.** How does a list of the same lines produce different bytes?
And are those lines part of the tool definitions or part of the prompt?

**Mechanism.**

- Guidance is emitted per tool, from the effective names in this request's snapshot, so a tool
  narrowed away by permission contributes no guidance at all.
- Three gates: the shell adds two lines, write adds one, and edit adds one. The write and edit
  lines restate the contract as an operating rule.
- The order is fixed: shell, then write, then edit. It is not derived from registration order,
  which can vary and would vary the bytes with it.
- The shell line carries its reason, because a prohibition with a reason attached is what models
  actually follow.

**Takeaway.** Guidance is a function of the tool set, and the function has to be deterministic.

**Hand-off.** The co-host asks why the order of the parts matters at all.

## Beat 4 — Order is an economic decision (648 words, EXPERT here)

**Claim.** The instruction sources are ordered for the cache, not for the reader.

**Source.** 4.2 ordering, with the ordering comment from 4.1.

**The question the co-host raises.** Putting the date and environment first is the natural order
for a person, so why is it backwards for the machine?

**Mechanism.**

- Providers cache a prefix: two requests sharing a byte-identical prefix make the second a cache
  hit up to the first difference.
- So the order runs most shared to least: user-level catalog and guidance, then project
  instructions, then the date and environment, which vary by day and by directory.
- The rejected alternative ranks by importance, which optimises how the model reads rather than
  how the cache works; the most cache-stable content is usually the least session-specific, and
  a miss is paid on every step.
- The tail sources render their change as a supersession, and the invariant is testable: change
  only the date and assert the first part is untouched.

**EXPERT.** Why the date goes last: order by how long a line can sit still, not by how much it
matters to a reader. Three turns, in and out.

**Takeaway.** Put the least session-specific content first, because the cache rewards the
longest shared prefix.

**Hand-off.** The co-host sets up the artifact.

## Terms to define on first use

- **Selection** — the frozen identity of a request: session, agent, instruction sources, tools.
- **Loading** — adding the resolved model and the active history to a selection.
- **Instruction baseline** — the frozen text of every instruction source at the current epoch.
- **Tool guidance** — the conditional lines spliced into the base prompt for the tools present.
- **Prefix cache** — the provider's reuse of a byte-identical prefix, billed as a hit.
- **Supersession render** — wording a changed value as a replacement, such as the date is now.

## Do not say in this episode

- "just", "simply", "obviously", "basically", "leverage", "utilize"
- "Part four", "Appendix A", "D8", "D23", or "figure"
- the words schema or hash where "data shape" or "fingerprint" will do
- "turn" for a step, and "step" for an execution
- "compaction" for a checkpoint, or "snapshot" for the tools frozen in the selection
- a file path, a column name, or a placeholder spelled as code
