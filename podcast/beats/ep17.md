## Beat 1 — The step brackets itself

- **Claim:** Every step fingerprints the working tree before it talks to the model, and again
  after it finishes.
- **Source:** 10.1, Snapshots.
- **Co-host raises:** "That sounds like a backup, and backups are expensive." Then: "There is a
  window where a tool could write before the capture lands."
- **Mechanism:**
  - A snapshot is a capture of the Location-scoped working tree at one instant. The
    representation is a content-addressed tree, so comparison is by object identity and an
    unchanged file costs nothing to prove unchanged. The identifier travels as an opaque token.
  - Rejected: diffing against a previous request state that does not exist until you define it;
    a filesystem watcher that is racy and does not survive a restart; full copies per step,
    which are correct and wasteful.
  - Capture is best-effort. Disabled, unsupported, or failed returns nothing and the step runs
    anyway. The start capture is forked as a fiber and awaited at the step's first durable
    publish, so the start tree exists before the first local tool can mutate the disk.
  - Capture covers the project scope only: outside-project paths, ignored paths, and untracked
    files over a size cap are not in the tree.
- **Takeaway, as spoken:** "Fingerprint the tree before the first tool can touch it, and
  compare by identity, not by replay."
- **Words allocated:** ~620 (actual 643).

## Beat 2 — Names on the record, patches on demand

- **Claim:** The step stores two snapshot ids and the changed paths. It does not store the
  patch.
- **Source:** 10.2, Diffs and per-step files.
- **Co-host raises:** "That is the part I would get wrong. A diff is what people want. Why not
  save it?"
- **Mechanism:**
  - Listing changed paths walks two trees and returns project-relative names without loading
    contents or generating patches. Generating diffs produces, per file, the path, the status,
    the addition and deletion counts, and the unified patch at a chosen context width.
  - The projector folds the start id, the end id, and the path list onto the assistant message.
    Equal start and end short-circuits to an empty list, and "no snapshot" (absent) is kept
    distinct from "no changes" (empty).
  - A turn diff compares the range's first recorded start with its last recorded end, and
    substitutes the working copy while the final step is still running. A range spanning a
    location switch is rejected rather than diffed.
  - Rename detection is off on purpose so both the old and new path appear, which is what
    revert needs. Patch output is bounded by a byte budget.
- **Takeaway, as spoken:** "Names on the record, patches recomputed from trees that cannot
  change."
- **Words allocated:** ~620 (actual 648).

## Beat 3 — Undo is three moves

- **Claim:** Undo is three operations, and only the last one is destructive.
- **Source:** 10.3, Revert.
- **Co-host raises:** "A button is a button. Why three?" Then: "Now the original. Why keep it
  after you already restored the files?"
- **Mechanism:**
  - Stage captures the current tree as the original, builds a restore plan, applies it, and
    stores the boundary plus the original on the session row. A second stage keeps the first
    stage's original, so the escape hatch does not move.
  - The plan walks forward from the boundary and keeps the earliest start snapshot per file, so
    a file touched by several steps rewinds to before the first touch. A path absent from that
    tree is deleted, which undoes a creation.
  - Clear restores the original over the touched files and drops the boundary. A stage followed
    by a clear leaves the working tree as it was.
  - Commit publishes; the projector deletes every message at or after the boundary, deletes
    inbox rows enqueued at or after the boundary, clears the revert state, and resets
    instruction state. Stage, clear, and commit all reject an active session.
- **Takeaway, as spoken:** "Stage restores and holds the door open. Clear walks back out.
  Commit closes it."
- **Words allocated:** ~620 (actual 631).

## Beat 4 — What undo cannot reach

- **Claim:** Revert returns content, not consequences.
- **Source:** 10.3, Revert, the unsupported set.
- **Co-host raises:** "Correct and useless are not the same thing." And later: "'cannot undo'
  sounds like a defect list. Is it?"
- **Mechanism:**
  - Files outside the captured scope: outside the project, ignored paths, and untracked files
    over the capture cap were never in any tree, so restore cannot touch them.
  - Effects that are not file content: network calls, remote systems, and process state. Revert
    returns bytes, not side effects.
  - Runs that were not idle: stage, clear, and commit refuse an active session rather than
    applying a restore underneath a mid-write execution.
  - History before commit, and content versus metadata. Stage restores files but leaves the
    messages, so showing the reverted history before commit shows uncommitted history.
    Content-addressed trees restore bytes, not ownership or timestamps.
- **Takeaway, as spoken:** "Snapshot, subtract, and be clear about what you kept."
- **Words allocated:** ~620 (actual 622).

## Terms to define on first use

- **snapshot** — a capture of the working tree at one instant.
- **content-addressed tree** — a representation where identical content is the same object, so
  equality is meaningful and comparison is cheap.
- **changed paths** — the project-relative names that differ between two snapshots.
- **diff** — the structured per-file patch between two snapshots.
- **turn (range)** — the stretch of steps opened by a prompt after the previous idle marker and
  closed at the next idle marker.
- **stage** — restore files and hold the original, leaving history intact.
- **clear** — undo a stage by restoring the original.
- **commit** — delete history and pending input at and after the boundary.
- **original** — the working tree captured when a stage began, kept as the escape hatch.

## Do not say in this episode

- "backup" as a synonym for a snapshot. The first beat rejects it explicitly.
- "record" as a bare noun (the engine stresses the second syllable). Say "the step's entry",
  "the history", or "what was written down".
- "just", "simply", "obviously", "basically".
- "checkpoint" for revert. A checkpoint is what a compaction leaves behind.
- Any claim that revert reverses a network call, a deploy, or a migration.
- "Part ten", "Appendix", or any diagram id.
- Any file path, identifier, or code fragment in a spoken line.
