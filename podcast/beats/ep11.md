# Episode 11 beats — Lowering to messages

Production beat sheet. The script in `../scripts/ep11.md` was written from this. Times are
spoken words at about one hundred and fifty words per minute.

**Total:** 3,365 words. **Beats:** four, about six hundred and twenty-five words each.
**Artifact:** the conversation-checkpoint wrapper, read in segment eight.

---

## Beat 1 — One message in, many out

**Claim.** Lowering is a translation that is allowed to change the number of messages: one
projected message can become several provider messages, or none.

**Source.** Topic 4.7, Part 4. `packages/core/src/session/runner/to-llm-message.ts`, the
per-type switch and the assistant renderer.

**Co-host raises.** "One message in, one message out." The case that breaks it: an assistant
message with text, reasoning, and two local tool calls becomes an assistant message plus
separate tool-result messages.

**Mechanism.**
- One assistant message carries many content items; lowering splits them into content parts.
- Tool results for tools the agent ran become their own messages. Hosted tool results ride
  along with their call.
- Idle and agent-switched messages lower to nothing. A model switch lowers to an effort-change
  message only when both variants are reasoning-effort variants on the same provider and model.
- The function is a switch over message types, then two normalizations that take the target
  model as an argument. It has no side effects, so it is testable without a session.
- An empty result is correct when every part filters out. Emitting an empty assistant message
  is not.

**Takeaway, as spoken.** "Lowering is a pure translation from your history to the wire, and
the count is allowed to change."

**Words.** 631.

## Beat 2 — Metadata is proof

**Claim.** Provider metadata is a signature that only the producing model can present, so it
replays only where it can be verified.

**Source.** Topic 4.7, Part 4. The `reuseProviderMetadata` flag and the call-side and
result-side tool metadata rules in `to-llm-message.ts`.

**Co-host raises.** "The transcript is the transcript. If the model produced it, you can send
it back." The case: switching models mid-session while the transcript still holds encrypted
reasoning and thought signatures.

**Mechanism.**
- One flag: same provider, same model, and the message did not fail. Text and reasoning
  metadata replay only under it.
- Reasoning replays as reasoning only when the flag holds and the reasoning completed. After a
  switch, readable reasoning is downgraded to text, and reasoning with no text is dropped.
- Call-side tool state is model-scoped proof. It replays for the producing model, including a
  completed or errored hosted tool of the same model.
- Hosted result payloads are provider-format data, so they replay across models of the same
  provider. A model switch echoes the payload, never the call-side state.

**Expert.** One appearance, three turns. The counterintuitive point: a failed message's
metadata is not trusted even on the same model, because we cannot be sure what was signed.
Metadata is proof, not content.

**Takeaway, as spoken.** "Metadata is a signature, not content. Replay it only where it can be
verified."

**Words.** 639.

## Beat 3 — Attachments and bounds

**Claim.** A request should never fail because of its shape, so lowering replaces what the
target cannot carry and states what it replaced.

**Source.** Topic 4.7, Part 4. Attachment lowering, `unsupportedParts`, and `boundImages` in
`packages/core/src/session/model-request.ts`.

**Host states the naive position, and the co-host answers it.** "The transcript is the truth,
so send it exactly as it is." The case: a large screenshot plus a document the target model
cannot read kills a long session at the provider.

**Mechanism.**
- Attachments lower by type: plain text inlined with a header, a directory listed, images and
  documents as encoded media with a location line for local files, everything else dropped.
- Duplicate inline images with the same mention, name, description, and type are removed.
- A model-aware pass replaces unsupported media with an explanatory text part, including a
  type a particular provider rejects for its own reasons.
- A second pass measures total inline image bytes. Above the trigger it replaces images with
  a marker, oldest first, until the total is below the target.
- The marker says the image was removed, forbids claims from memory, and says to retrieve it
  again if it matters.

**Takeaway, as spoken.** "A request should never fail because of its shape. Replace what
cannot travel, and say what you replaced."

**Words.** 633.

## Beat 4 — The checkpoint

**Claim.** A summary is a record, not a command, and the checkpoint wrapper has to say so in
words because the only role available for it is the user role.

**Source.** Topic 4.7, Part 4, and Appendix A, group Compaction, for the wrapper. The
compaction branch in `to-llm-message.ts` and the native-window path.

**Host states the naive position, and the co-host answers it.** "A summary is text, so hand it
to the model as a summary." The case: the summary contains the user's earlier imperative, and
the next step executes it as new work.

**Mechanism.**
- An incomplete compaction lowers to nothing. A native checkpoint decodes its stored provider
  messages, and history selection keeps only windows the target model can replay.
- A local summary becomes one user message: an opening checkpoint tag, the historical-context
  sentence, a summary section, an optional recent-context section, and a closing tag.
- The recent section is the newest messages kept verbatim, not model-written text.
- The update prompt is told not to reproduce the wrappers, so checkpoints stay singular across
  compactions.

**Takeaway, as spoken.** "A checkpoint is a user message that says, in words, do not treat
this as a new instruction."

**Words.** 636.

## Terms to define on first use

- **Lowering** — translating projected session messages into provider messages and content
  parts.
- **Provider message** — the wire shape: a role and content parts. Not the same object as a
  session message.
- **Content part** — one piece of a provider message: text, reasoning, a tool call, or a tool
  result.
- **Hosted tool** — a tool the provider runs itself; its result arrives in the provider's
  format.
- **Provider metadata** — signed or provider-specific state attached to content. Proof, not
  readable content.
- **Thought signature** — one provider's signed state on a text part, tied to the model that
  produced it.
- **Reuse flag** — same provider, same model, and no error. Every metadata decision derives
  from it.
- **Native checkpoint** — a stored provider-format window that can be decoded directly.
- **Checkpoint** — the durable record a compaction leaves behind, as later requests see it.
  Not the act of compacting.
- **Attachment lowering** — turning files into inline text, listings, encoded media, or
  nothing.

## Do not say in this episode

- "Part seven" or "Appendix A". Refer to other episodes by number and title.
- "Compaction" when the checkpoint is meant. The compaction is the act; the checkpoint is what
  it leaves behind.
- "Turn" for a step. A step is one model call.
- "Schema", "serialize", or "payload" in a spoken line where a plain phrase will do.
- Any identifier: "toLLMMessages", "providerState", "providerResultState", "boundImages".
- Byte counts as digits. Say "twenty-five megabytes" and "fifteen".
- "Just", "simply", "basically", "leverage", "utilize".
