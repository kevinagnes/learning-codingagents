# Episode 12 beat sheet — Agents and subagents

Production sheet. Not read aloud. Four beats, each with the same four moves. Word
allocations are the delivered counts.

## Beat 1 — An agent is a configuration record

- **Claim.** "An agent is not a personality. It is a configuration record that a session
  points at, and everything in the assembled prompt is built around it."
- **Source.** Topic 4.8 (Part 4, context assembly).
- **Example / edge the co-host raises.** The co-host calls it a config file with extra
  steps, then asks where the behaviour lives. The answer is what the record narrows:
  instruction sources, skills, the tool protocol servers, and the tool snapshot, all
  filtered by the merged ruleset.
- **Mechanism.**
  - The record carries identity, an optional preferred model, request settings, an optional
    system override, an optional description, mode, hidden, an optional step limit, and a
    permission ruleset.
  - The system field is a full replacement for the generated base prompt, not a patch. A
    partial override would duplicate instructions.
  - Mode is primary, subagent, or both. Hidden keeps internal agents out of user-facing
    selection. The mode lets one record answer the session picker, the subagent tool, and
    the interface list.
  - The default constructor starts with a broad allow, then asks for secret environment
    files, then allows the example file. The step limit bounds one execution and turns
    tools off at the limit so the model summarizes.
- **Takeaway.** "An agent is the bundle of decisions a session runs under. The prompt is one
  of those decisions, not the whole thing."
- **Words.** 638.

## Beat 2 — Who gets chosen

- **Claim.** "Which agent answers your first message is decided by an ordered rule, and the
  rule filters before it orders."
- **Source.** Topic 4.8 (Part 4).
- **Example / edge the co-host raises.** The helper from the cold open was a candidate
  because its mode or hidden flag was never written down. The co-host pushes on the
  special-cased build name.
- **Mechanism.**
  - Selectable means the agent exists, its mode is not subagent, and it is not hidden.
  - Default resolution tries the configured default, then build, then the first selectable
    agent. The filter runs inside every step of the walk.
  - An explicit identifier bypasses the filter so the subagent tool and a direct user
    choice can reach subagents. A missing agent becomes an error, failing the step rather
    than running an unconfigured prompt.
  - The list returns every agent with the selected one first.
- **Takeaway.** "Selection is not a sort. It is a filter with a fallback order."
- **Words.** 642.

## Beat 3 — Inheritance and the ceiling

- **Claim.** "A subagent inherits from its parent in a fixed order, and the chain of
  inheritance has a hard ceiling."
- **Source.** Topic 9.4 (Part 9, concurrency and sessions); topic 4.8 for the step limit.
- **Example / edge the co-host raises.** A child on a different model shows up on a bill;
  a helper that spawns helpers is a fork bomb. The co-host also asks what the child
  receives, and what happens on a foreign continuation.
- **Mechanism.**
  - The child's model resolves as explicit argument, then the agent's configured model,
    then the parent's model. Switching agent on a continued child switches its model too
    unless a model was passed explicitly.
  - Depth is counted by walking the parent chain before creating the child, not by a global
    counter. The configurable limit defaults to one.
  - Spawning is a permissioned action named subagent, with the agent identifier as the
    resource, so a ruleset can allow one helper and deny another. The roster the model sees
    is filtered the same way.
  - A fresh child is told it is a subagent, because it has none of the parent's framing.
    Continuing requires the child to belong to the calling session.
  - **EXPERT** appears here, once: why a subagent is a child session rather than a nested
    function call. Entry line: "This is the part where the choice looks wrong, so here is
    the person who made it." Four turns. Point: a stack frame cannot be observed, resumed,
    or stopped on its own, and the tool call is a handle while the work is a session.
- **Takeaway.** "A subagent is a session because a function call cannot be observed,
  resumed, or stopped on its own."
- **Words.** 626.

## Beat 4 — Foreground, background, and the notice

- **Claim.** "Foreground and background are the same job with two different waits."
- **Source.** Topic 9.4 (Part 9).
- **Example / edge the co-host raises.** A parent that backgrounds work it needs next will
  poll or sleep, or duplicate the child's edits. The co-host asks what the parent model
  gets, and why the result arrives as a message rather than a return value.
- **Mechanism.**
  - Starting a child registers a job with a completion signal. Foreground blocks on the
    signal, racing finished against backgrounded. Losing that race releases the wait without
    cancelling the child.
  - Background returns immediately with the child identifier and a text that forbids
    sleeping, polling, asking for status, and duplicating the work, then offers an
    alternative.
  - On any terminal state, completed, failed, or cancelled, an observer admits a synthetic
    message into the parent, tagged with the child identifier and state. A suspended parent
    stores it without waking.
  - The notification identifier clears the durable marker exactly once, so a restart sweep
    acknowledges orphaned background work instead of announcing the same completion twice.
- **Takeaway.** "Background work reports by admitting a message into the parent, not by
  returning a value."
- **Words.** 606.

## Terms to define on first use

- **agent** — the configuration record a session runs under.
- **primary agent** — an agent that may be chosen as a session's default.
- **subagent** — a child session started by the subagent tool.
- **selectable** — exists, not subagent mode, not hidden.
- **depth limit** — the maximum nesting of the parent chain.
- **foreground / background** — the two waits on a child job.
- **synthetic message** — a message admitted into a session by the system, not by a user.

## Do not say in this episode

- "turn" for a step. A subagent's completion is a message, not a turn.
- "queue" for anything. No input is being queued in this episode.
- "execution" as a synonym for a step.
- Any code identifier, flag name, file path, or configuration key.
- "recursion limit", which is not the term the implementation uses for the depth guard.
