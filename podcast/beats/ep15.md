# Episode 15 beat sheet — Context is finite

Production sheet for `scripts/ep15.md`. Not spoken. Topics 7.1, 7.2, 7.3, and 7.4 of
`07-compaction.md`, plus the summary template and rules from Appendix A, group Compaction.

**Cold open hook:** a compacted session resumes and asks which branch you are on.
**Promise:** describe the checkpoint: what goes in the summary, what stays verbatim, and what
the agent refuses to lose.
**Rule for the recap:** compact to a summary plus the newest exchange.
**Host share:** HOST 74 percent, CO-HOST 26 percent of spoken words; EXPERT appears once.

## Beat 1 — You cannot weigh the parcel before you post it

**Claim.** You cannot ask the provider how big your prompt is. You can only ask what the last
one was.

**Source.** 7.1, Part 7.

**Example the co-host raises.** "Why not count it locally. A tokenizer is a library." Local
counting is low on dense text and pessimistic counting compacts a conversation that still had
room.

**Mechanism.**

- Measured: the newest same-provider assistant message's reported usage, which covers input,
  cache reads, cache writes, output, and reasoning.
- Estimated: about four characters per token for everything after that anchor, with a fifteen
  percent margin when the agent sizes the reply.
- The anchor's own message is excluded because its usage already covers it, while its local
  tool results are counted because the provider never saw them.
- Same-provider-only is a correctness rule: another provider's count may describe a native
  window this model cannot replay.
- An unknown window counts as zero and gives an infinite ceiling, so automatic compaction never
  fires; a native checkpoint estimates as nothing, so the agent waits for a real response.

**Takeaway, as spoken.** You cannot weigh the parcel before you post it, so you use the last
receipt and weigh what you added.

**Words allocated.** 638.

## Beat 2 — The ceiling is not the window

**Claim.** The ceiling is not the window. The gap between them is the reply you are asking for.

**Source.** 7.1, Part 7.

**Example the co-host raises.** Fill the window and the model has no room to answer; compact to
free space and the summary has nowhere to go either, so compaction eats itself.

**Mechanism.**

- The reserve is ten percent of the window or sixteen thousand tokens, whichever is larger;
  the summary request is capped at the same ceiling, so the reserve is also its budget.
- Three sizes: the context window, an optional separate input limit, and the output limit. The
  budget uses the input limit when there is one and falls back to the window.
- Automatic compaction is due only when the estimate reaches the ceiling, the last message is
  not a completed compaction, and a same-provider measurement is newer than the latest
  checkpoint.
- A settings override supplies an explicit reserve; manual compaction works even when automatic
  compaction is switched off.

**Takeaway, as spoken.** A budget without a reserve is not a budget. It is a wall.

**Words allocated.** 657.

## Beat 3 — Make it smaller, not again

**Claim.** A rejected request is not retried. It is made smaller.

**Source.** 7.2, Part 7.

**Example the co-host raises.** The estimator said the request fit and the provider disagrees.
Retrying the same request fails the same way.

**Mechanism.**

- Three triggers: auto before the request is sent, manual from an inbox control item, and
  overflow detected during a step, which compacts and then restarts the step from the new
  checkpoint.
- The shrink ladder aims at seventy, then fifty, then thirty-five percent of the first rejected
  request's size, recomputed from that first rejection rather than the current request.
- Payload-too-large is a byte problem, usually inline media; the first time it happens the
  agent resends the same content as text, which costs no shrink step.
- Flattening to text drops reasoning, media, instruction updates, and long tool outputs; whole
  exchanges are then dropped oldest first, and the newest exchange is never dropped.
- Room is reserved for the omission note before anything is kept, and a failure says the
  request cannot be reduced further without losing the latest exchange or checkpoint.

**Takeaway, as spoken.** Shrink by whole exchanges, from the first rejected size, and stop
before you drop the newest one.

**Words allocated.** 637.

## Beat 4 — A handoff note, not a summary

**Claim.** Compaction does not summarise your conversation. It writes a handoff note and keeps
the newest exchange word for word.

**Source.** 7.3 and 7.4, Part 7; Appendix A, group Compaction.

**Example the co-host raises.** A vague summary makes the next agent confidently wrong: wrong
branch, re-read files, forgotten constraints.

**Mechanism.**

- The split keeps the newest messages within about fifteen thousand tokens as verbatim text,
  starts at a user message so tool calls and results stay together, and always keeps the newest
  exchange.
- The summary is a fixed template plus a rules block; the reply must contain a template
  heading, one nudge is sent on a miss, and a second miss fails.
- Later compactions update the existing checkpoint: newer history takes precedence, completed
  work leaves Active, resolved blockers and answered questions are removed, and the wrapper
  tags are not reproduced.
- A checkpoint containing a legacy catch-all heading is rewritten once at the current level of
  detail.
- Native compaction returns an opaque window instead of text; provenance is a hash of the
  endpoint, checked before compaction, after any request hook, and at replay, and a mismatched
  checkpoint is skipped with the original transcript as the fallback.

**Takeaway, as spoken.** Compact to a summary plus the newest exchange, and replay an opaque
window only where it was made.

## Terms to define on first use

- **measured** — the provider's own reported usage for the newest same-provider response.
- **estimated** — a local character count for text that arrived after that anchor.
- **ceiling** — the window minus the reserve; the request may reach it, the reserve belongs to
  the reply.
- **reserve** — ten percent of the window or sixteen thousand tokens, whichever is larger.
- **auto, manual, and overflow** — the three reasons compaction starts.
- **shrink step** — one reduction target, at seventy, fifty, or thirty-five percent of the
  first rejected size.
- **exchange** — a user message and everything after it up to the next user message.
- **checkpoint** — what a compaction leaves behind; not a synonym for compaction.
- **provenance** — the hashed identity of the endpoint that produced a native checkpoint.

## Do not say in this episode

- "summary" for the whole checkpoint — the summary is the text part, the checkpoint is the
  artifact that also carries the verbatim recent window.
- "compaction" for a checkpoint, and "checkpoint" for the act.
- "retry" for the overflow path — the request is shrunk, not retried.
- "prune" or "trim" for messages — exchanges are kept or dropped whole.
- "turn" for a step, and any digit, identifier, path, or diagram label.
