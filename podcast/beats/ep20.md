## Beat 1 — The order, and why durability comes first

**Claim.** The build order is not a preference. Durability precedes concurrency, and
settlement precedes features.

**Source.** Topic 12.1, the concept section and the ladder preamble.

**Example the co-host raises.** "Why not add persistence at the end? The loop works in a day,
and persistence is a week of plumbing that makes the demo slower." Later: "You said each
milestone is a gate, not a phase. What does that mean when I am moving fast?"

**Mechanism.**

- A concurrent system with no durable record has nothing to serialize on. Two fibers over an
  in-memory transcript corrupt it, and one execution per session becomes a lock over a
  structure a crash dissolves.
- Once the message, the tool result, the claim, and the inbox item are rows, concurrency is a
  query plus a doorbell, and steering is an ordered promotion over durable rows.
- The first four milestones build the record and the projection. Only then does anything
  concurrent appear.
- The corollaries follow the same test: model boundary, durable state, continuation, tools,
  permissions, compaction and reliability, concurrency, snapshots, server last. Each milestone
  is a gate, and its test still passes after the next one lands.

**Takeaway, as spoken.** "Build the record first, because every concurrent feature later is a
query over it, not a new argument about who owns what."

**Words.** 580. HOST 390, CO-HOST 190.

## Beat 2 — The smallest agent that is correct

**Claim.** The smallest correct agent is one streamed model call, two tools, a bounded result,
and one continuation decision you can read.

**Source.** Topic 12.1, "Build it": the minimum-viable agent for M0 and M1.

**Example the co-host raises.** "Ninety lines is a demo, not an agent." Later: "Allowed. That
is a strong word for the thing you banned in the first episode."

**Mechanism.**

- A stream must end in a terminal event. A stream without one is a failure, and an event after
  the terminal is also a failure.
- The tool set is fixed before the request is sent. A returned call is validated once, and a
  bad shape becomes an error the model can read and correct.
- The result is bounded to a head plus a marker naming the file that holds the rest.
- Continuation is derived from the finish reason and the tool states. At M1 it lives in a
  variable, and the comment names M2 and M3 as the milestones that remove it.
- History becomes durable and sequence ordered; each shortcut that remains is named, including
  the one that is actively wrong, which is returning a refusal as text.

**Takeaway, as spoken.** "The minimum agent is a stream that must end, a tool set fixed before
the request, a result with a ceiling, and one decision read from what came back."

**Words.** 667. HOST 483, CO-HOST 184.

## Beat 3 — Pitfalls, part one: the loop and the record

**Claim.** The first two pitfall families are one mistake each. A loop that decides twice, and
a fact treated as true before it is written down.

**Source.** Topic 12.2, the catalog table and the layered explanation, loop and durability
layers.

**Example the co-host raises.** "Give me the temptation first, then the symptom." Later: "Four
fixes for four symptoms sounds like a checklist. Why not handle each symptom where I see it?"

**Mechanism.**

- In-memory tool loop: after retries or compaction, the model is called twice in one step, or a
  result lands after settlement. Two places decide continuation. Fix: one call per step, with
  continuation from the record.
- Continuation from memory: after a crash the agent stops early or re-runs a tool. The boolean
  died with the process. Fix: derive it from tool states and the finish reason.
- Non-durable tool results: a call has no result after restart, or the model invents one. Fix:
  publish the call before executing, settle after.
- No write-ahead claim: a step runs twice, or a finished turn resumes on every boot. Fix: the
  claim is written in the started transaction, and a surviving claim with no terminal is the
  crash signature.

**Takeaway, as spoken.** "If a decision can be re-derived after a restart, do not keep it in a
variable. If a fact has to survive, write it before you act on it."

**Words.** 637. HOST 460, CO-HOST 177.

## Beat 4 — Pitfalls, part two: context, permission, and crash

**Claim.** The remaining pitfalls all let something leak: a size, a refusal, or a partial truth.

**Source.** Topic 12.2, the catalog table and the layered explanation, context, control, and
concurrency layers.

**Example the co-host raises.** "Half of these are not crash problems. Why put the crash in the
same beat?"

**Mechanism.**

- Context: bound output with a marker; keep the newest exchange word for word; reconcile an
  initial summary with an update instead of re-summarising a summary; keep a stable prefix and
  the tools on the terminal step.
- Control: a decline travels as a defect and resurfaces typed at one place; a decline with
  feedback stays typed so the model can continue.
- Bounding work: a per-turn step allowance, and a terminal step that keeps the tools advertised
  but refuses to run them.
- Concurrency: one execution per session, and a second wake rings the doorbell instead of
  starting a fiber.

**Takeaway, as spoken.** "Fix the layer, not the symptom. A retry after a refusal is an error
channel bug. A duplicated answer is a loop bug. An overflow is a budget bug."

**Words.** 676. HOST 523, CO-HOST 153.

## Terms to define on first use

- **Milestone** — one rung of the build ladder, with one goal and one invariant.
- **Gate** — a milestone whose test must pass before the next starts and must still pass at the
  end. Not a phase.
- **Invariant** — the one rule a milestone introduces and later milestones only read.
- **Terminal event** — the event that ends a model stream. A stream without one is a failure.
- **Settlement** — writing the terminal durable facts for a span of work.
- **Write-ahead claim** — the durable marker written before work runs and released at a
  terminal.
- **Defect tunnel** — carrying a decline past fault-tolerant boundaries so it cannot become
  model-visible output.
- **Doorbell** — the pending wake that makes a running execution drain again instead of starting
  a second fiber.
- **Content-addressed capture** — a snapshot named by the hash of its contents.

## Do not say in this episode

- "Phase" for a milestone. The episode's point is that a milestone is a gate.
- "Turn" for a single model call. A turn is the stretch until the session would go idle.
- "Execution" for a step. An execution is one busy period.
- "Queue" as a synonym for steering. Steering changes work in progress; queued work starts new
  work when the session would idle.
- "Checkpoint" for the act of compacting. Compaction is the act; a checkpoint is what it leaves.
- "M zero" as a code label. Say "milestone zero."
- Any file path, code identifier, prompt text, or diagram label.
- "Just," "simply," "obviously," "basically," "leverage," "utilize."
