# Episode 5 beat sheet — The drain and step machine

Production sheet for `scripts/ep05.md`. Four beats, one artifact, one rule. This is the
structural centre of the season: after this episode a listener can draw the loop as decide,
prepare, run one step, record, decide again.

**Topics:** 3.1–3.5 · **Cast:** HOST, CO-HOST, EXPERT (once) · **Words allocated:** about
3,340 total, four beats of roughly 635 each · **CO-HOST share:** about 26 percent

---

## Beat 1 — Four phases, not one function

**Claim (spoken).** "The agent loop is one function with a while statement in it."

**Source.** Part 3, § 3.1, "The concept" and "The real thing".

**Example the co-host raises.** A retry written inside the same loop: the function can no
longer tell a retry from a continuation, so it cannot know whether new input may be promoted.

**Mechanism.**

- Four named phases, each owning one decision: the drain (is there eligible work, and loop
  over steps), preparing the next step (serialize the inbox, handle a control, promote,
  reload context), the run step function (one step's policy), and the attempt (one try).
- The three exits are a type, not a convention: complete, moved, reloaded.
- Preparing runs under a mask that disables cancellation, so a check and its mark cannot be
  split; cancellation returns for the expensive parts.
- Only the step number and the continuing flag cross a step boundary. Everything else is
  reloaded, which is why a crash between steps needs no special case.

**Takeaway (spoken).** "Four phases, one decision each, so the next action is read from what
was written down."

**Words allocated.** about 635 (HOST about 460, CO-HOST about 175).

## Beat 2 — A retry is not a resumed stream

**Claim (spoken).** "When a stream fails halfway, you resume the same stream."

**Source.** Part 3, § 3.2, "The concept"; Appendix A, A.7 and A.8.

**Example the co-host raises.** The connection drops after the user has read half an answer.
A transparent retry would write that half again and the transcript would contain it twice.

**Mechanism.**

- The attempt makes exactly one model call and reads the stream to the end so the next
  request can reuse the response.
- Whether output has started is the wall: no output means a transparent retry; output started
  means a continuation with a synthetic nudge and a new assistant message.
- The record is a small fold of what the step published, read as an immutable snapshot;
  continuation is derived from the local tool states, and the finish reason is a closed set.
- The two loops are nested: one over attempts of the same step, one over steps. Only the outer
  loop moves the step number.

**Expert beat.** `EXPERT` appears once, after the takeaway is set up. One point only: a retry
is a new attempt, not a resumed stream, because the step owns the request and the attempt owns
one try. Not the episode one argument about one call per step.

**Takeaway (spoken).** "A retry is a new attempt for the same step. A continuation is a new
step."

**Words allocated.** about 635, including `EXPERT` at about 120 (HOST about 340, CO-HOST
about 175).

## Beat 3 — Six ways a step can end

**Claim (spoken).** "A step ends in one of two ways. It finished, or it failed."

**Source.** Part 3, § 3.2, "The diagrams" and "The real thing".

**Example the co-host raises.** A provider rejection because the request is too long, before
any token arrives. Nothing is broken, so failed is the wrong word. And a length stop, where
the model did not finish, so finished is the wrong word.

**Mechanism.**

- Six outcomes: completed, retry, continue, output limit, compacted, recover full.
- They are chosen in a fixed order: overflow with no output, then transport full recovery,
  then retryable with no output, then retryable with output started, then a length finish,
  then completed.
- Compacted and recover full each spend their allowance at most once per step.
- The output-limit streak reads the newest three entries; three assistant finishes on length
  fail the step with a typed error. Any other finish, or new user input, breaks the streak.
- The step limit is not an outcome. It is a policy applied before the request is built.

**Takeaway (spoken).** "Continuation is data. The step returns a decision, and the loop acts
on it."

**Words allocated.** about 635 (HOST about 460, CO-HOST about 175).

## Beat 4 — Tools inside the step, and the last step

**Claim (spoken).** "A step is the model talking. Tools happen after the step is over."

**Source.** Part 3, § 3.3, § 3.4, and § 3.5.

**Example the co-host raises.** Three tool calls in one response finishing at different
times, all wanting to append to the same assistant message. And an agent that would happily
call tools forever.

**Mechanism.**

- Each local call is forked into its own fiber, and only after the call event is durable.
- Two rules make concurrent publishers safe: commit the mark before the first await, and never
  require an order between sources.
- Work is interruptible; settlement is not. Unsettled calls are swept to a terminal, and a
  user decline propagates as a typed failure rather than model-visible output.
- The step allowance is per turn and resets on promotion. At the limit, the request keeps the
  tool definitions for the cache, says tools are not offered, and appends the maximum-steps
  prompt as an assistant message. The continuation flag is forced false, and the executor
  refuses a stray call with a short error.

**Takeaway (spoken).** "Tools live inside a step, and the last step has no tools."

**Words allocated.** about 640 (HOST about 460, CO-HOST about 180).

## The artifact

The maximum-steps prompt, read verbatim minus two typographic adaptations: the capitalised
heading is announced rather than read, and the three numbered requirements are spoken as
ordinals. The companion carries it exactly. Then the interpretation: the override clause,
the tail repetition, the assistant role, and the required response shape.

## Terms to define on first use

- **Drain** — one pass over the eligible durable work.
- **Step** — one model call and the durable record it produces.
- **Attempt** — one try at a single step; a retry is a new attempt for the same step.
- **Continuation** — the decision that another step should follow, derived from the record.
- **Execution** — one busy period for a session, from the first wake until it would stay idle.
- **Fiber** — a lightweight, interruptible unit of concurrency.
- **Settlement** — writing the terminal durable facts for a span of work.
- **Step allowance** — the per-turn, per-agent limit on model calls.
- **Terminal step** — the last step, where tools are not offered.
- **Turn** — the stretch from promotion until the session would go idle; contains steps.

---

## Do not say in this episode

- "turn" for a single model call. A turn contains several steps.
- "attempt" for a step, or for a retry. An attempt is one try inside a step.
- "execution" for one model call. It is one busy period for a session.
- "recover full" as a synonym for a retry. It rebuilds from the durable record.
- "checkpoint" for the act of compacting.
- Any restatement of Episode 1's expert argument about one call per step and the seam between
  asking and acting. This episode's expert point is retry versus continuation.
- Identifiers read aloud: the run step function, the preparation step, the continuation flag,
  the output-started field, tool choice, and the maximum-steps prompt are described, never
  spelled.
- "just", "simply", and any claim that a step is an entire answer.
